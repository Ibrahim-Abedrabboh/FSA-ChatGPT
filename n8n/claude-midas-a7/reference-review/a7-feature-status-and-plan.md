## Completion standard

**Fully implemented** applies to a narrowly named capability whose frontend/backend or engine behaviour is connected, deployed, and checked with suitable evidence. **Partially built** means there is working code or UI but an important handoff, feature branch or live verification is missing. **Not implemented** means there is no connected user capability. Test counts are supporting evidence, not a substitute for scenario coverage.

## Prioritized implementation plan

1. **Close the spending guard gap.** Every paid call, every branch, every retry; retain uncertain charges and make recovery explicit. This precedes new paid testing.
2. **Complete saved accepted-look and existing-image edits.** Bind approved base and immutable originals; implement add/remove/replace, no accidental white-background conversion, no invention of hidden parts or replacements.
3. **Restore the guide/Draft3 controls through the full contract.** Role, categories, outcomes, per-view side labels, exact output list, relevant room controls. Remove or disable controls the engine cannot apply truthfully.
4. **Finish collection/batch orchestration.** Independent cases, bounded dispatch, aggregation, errors, approvals and packages; no product collage.
5. **Finish Midas selections and deferred styling.** Verified supporting products, plants, mood and explicit focus with scene/support/occlusion checks.
6. **Finish delivery and operational experience.** Release matrix, truthful labels, usable downloads, original/current comparison, unsaved-draft protection, accessible states and usage visibility.
7. **Run the owner acceptance matrix.** Each journey gets concrete local/live evidence; only then promote the corresponding status to Fully implemented. Keep unresolved cases visible.
