# Glossary

*Business documentation · plain meanings of words used in this project*

| Term | Meaning |
|---|---|
| **A7** | The current version of the studio's image pipeline |
| **White master / white catalogue image** | The product alone on pure white, used in the catalogue |
| **Scene** | The product shown in a styled room (hero, wide or close-up view) |
| **Go 1** | Your approval of the plan before any image is drawn |
| **Go 2** | Your approval of a drawn image; the only thing that makes it "Approved" |
| **Reviewed candidate** | An image that passed the automatic check but has not been approved yet |
| **Repair** | A redraw you order at Go 2 to fix a problem; at most two per image |
| **Package** | The finished files (JPG, WebP, record) delivered after approval |
| **Contract** | The fixed list of what the image must show: pieces, count, colour, details |
| **Budget ledger** | The owner site's record of money reserved and spent on each paid step |
| **Owner site** | The private website where you start and approve jobs (preview and final versions) |
| **n8n** | The automation tool the pipeline was first built in |
| **Python service** | The project's own code that now runs the same pipeline (on Railway) |
| **Supervised paid run** | A test job with a spending cap that you approve and watch |
| **CI** | The automatic checks GitHub runs on every change |
| **PR (pull request)** | A proposed change, reviewed before it is merged |
